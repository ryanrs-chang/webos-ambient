# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Packaged LG webOS TV web app (clock + weather, always on, OLED). Bun + TypeScript, bundled to one script. No framework: themes are template strings rendered into the DOM. Target engine: webOS 26 (Chromium ≥ 120), weak CPU.

## Commands

- `bun test` — unit tests (`test/`); one file: `bun test test/burnin.test.ts`; one test by name: `bun test -t "every 9 consecutive draws"`
- Before calling a change done: `bun test && bunx biome check . && bunx tsc --noEmit -p . && bun run build`
- `bunx biome check .` (`bun run lint`; `bun run format` to fix) and `bunx tsc --noEmit -p .`
- `bun run setup` — writes `config.local.json` (interactive, or `--place/--lat/--lon/--tz` flags); `bun run check:secrets` — the leak guard (see Personal values)
- `bun run build` — `build:css` (Tailwind, `src/tailwind.css` → `app/style.css`, minified) then `build:js` (`scripts/build-js.ts`: `src/main.ts` → `app/main.js`, with the validated user config inlined as `__USER_CONFIG__`). Both outputs are generated and gitignored; `package` runs `build` first.
- `bun run dev` — build, then serve `app/` on :5173 and run the Tailwind watcher (`scripts/dev.ts`); `/fixture.json` is `test/fixtures/forecast.json`. `app/main.js` is built once: re-run `build:js` after editing a `.ts` file.
- `bun run package` / `install:tv` / `launch:tv` — see README
- `bun run font` — regenerate `app/fonts/ambient-sans.woff2` (`scripts/build-font.ts`: Noto Sans TC, pinned commit + sha256, subset with `uvx pyftsubset` to `fontCharset` = ASCII + Big5 symbols + Big5 level-1 hanzi + every non-ASCII character in `src/`), plus `app/fonts/OFL.txt` and `assets/fonts/charset.txt`; committed, not part of `build`. `test/font.test.ts` fails when a string in `src/` uses a character the committed font lacks: rerun it.
- `bun run icons` — regenerate `app/icon.png`, `app/largeIcon.png` from `assets/icon.svg` (needs `rsvg-convert`)

## Architecture

`src/main.ts` is the only DOM wiring; everything it calls is a pure, tested module. The runtime loop:

1. Startup: `defaultConfig` (`src/config.ts`, personal values inlined at build time) + launch params (`window.PalmSystem.launchParams` on the TV, the query string in dev) + persisted prefs (`src/controls.ts`, localStorage) decide the theme and brightness.
2. Data: `refreshForecast` fetches Open-Meteo via `src/weather.ts` every `refreshMinutes`; on failure it keeps the last forecast, marks it `stale` and retries in 60 s.
3. Render: `render()` builds a `ViewState` (`src/themes/types.ts`) and replaces `#content.innerHTML` with `themes[i].render(state)` — on start, every minute boundary (`tickMinute`), forecast change and theme switch. Because the DOM is rebuilt, continuity is restored after each render: `syncLoops` re-phases infinite CSS animations, the digit roll is driven by diffing against the previous time (`src/anim.ts`), then `syncBackdrop`/`syncEffects` update the layers below.
4. Motion: `relocate()` every minute moves `#stage` (burn-in, below; `placeStage()` only positions it after a render); `startEffects`/`startMeteors`/`startShimmer` run independently of renders.
5. Screen saver: `startKeepAwake` (`src/keepAwake.ts`) subscribes to tvpower's `registerScreenSaverRequest` and answers every request with `responseScreenSaverRequest` `ack: false`, so the TV's idle screen saver / Always Ready does not start, for at most `MAX_VETO_MS` (1 h) after start or the last remote key / `webOSRelaunch` (`poke()`), after which it answers `ack: true` so a TV left on still sleeps; it logs `[keepAwake]` to the console and is a no-op without a service bridge. `appinfo.json` deliberately has no `requiredACG` (adding it turns ACG enforcement on for webOS 26, and no listed group covers tvpower).
6. Home Assistant: when `haBaseUrl`, `haToken` and `haEntities` are set, `startHa` (`src/ha.ts`: pure WebSocket protocol `handleHaMessage`/`applyEntityEvent`, wiring with an injected socket factory and timers) subscribes to those entities; `src/indoor.ts` (pure, tested) classifies each by `device_class` or unit into temp / humidity / CO₂ / PM2.5 (first listed entity wins a slot) and every theme draws `indoorLine` under its weather: each value gets a band word from `CO2_BANDS` / `PM25_BANDS` / `HUMIDITY_BANDS` (thresholds and their sources are commented there), drawn brighter in a band worth acting on. New readings show on the next minute render (the first ones at once), never on every push. The token is never logged.
7. Input: remote keys (`keydown`, webOS keyCodes) and the `webOSRelaunch` event go through `applyKey` → `commit()`; the dev panel (`src/devpanel.ts`, localhost only) calls the same path.

DOM layers, back to front (`app/index.html`): `#backdrop` (ambient tint) → `canvas#effects` (weather particles, or the cinematic scene while that theme is active, never both) → `#meteors` → `#stage > #fade > #content` (the moving theme content) → `#hint`.

## file:// constraints

Packaged apps load from `file://`:

- The bundle is a classic IIFE script (`--format iife`), not an ES module; `index.html` uses a plain `<script src>`.
- Config is bundled (`src/config.ts`, personal values injected by `scripts/build-js.ts`); never fetch a local file at runtime.
- Only the forecast API is fetched over the network, plus the optional Home Assistant WebSocket (`src/ha.ts`).

## Personal values

The repo is public. Personal values (place, latitude, longitude, time zone, the Home Assistant URL and token) come only from `config.local.json` (gitignored, written by `bun run setup`), never from committed source, tests, fixtures or docs. `config.example.json` holds neutral placeholders; `src/config.ts` holds only non-sensitive tuning. Tests use `test/testConfig.ts` and never read `config.local.json`. A new user-settable key goes in `config.example.json`, `src/userConfig.ts` (`parseUserConfig`, with a test) and `scripts/setupArgs.ts`. `test/leakGuard.test.ts` fails if a value from `config.local.json` shows up in a committable file; do not weaken it.

## OLED rules

- Pure black background, thin gray text, no large bright areas (ambient tints stay under `#1a2333`).
- No seconds; the display changes once a minute.
- The content block visits the whole screen (`src/burnin.ts`, applied in `src/main.ts`) by relocating, not by drifting: a continuous drift left the text mid-transition at sub-pixel positions, which looked blurry on the TV, so between relocations `#stage` sits still on whole pixels. Its position is `floatMargin + zone anchor`, computed by the pure `stagePosition` (anchor fraction x `floatRange`, rounded and clamped, so always an integer `translate`); `placeStage()` applies it at start, after every render/theme switch (the range depends on the content size) and on each relocation jump. `#stage` has no transform transition and no `will-change`; never add either. Every `relocateMinutes` (1), at `relocateOffsetSec` (:30, never the :00 digit roll) past the minute, `relocate()` fades `#fade` out over `relocateFadeMs` (1200), jumps to a point in the next zone of a shuffled 3x3 bag (`zoneBag`/`nextZone`/`zoneTarget`: every region once per 9 relocations, never the same twice in a row), and fades back in. The anchor is stored as a fraction of the free range so a theme of another size keeps its zone. Reduced motion still relocates, without the fade. The margin and the three relocate settings are in `src/config.ts`. Themes must stay content-sized with real room to move (forecast is 1450 px wide). Do not add static elements outside `#stage`, other than `#hint` (shows for 2 s), `#meteors` (empty except for one moving, dim meteor at a time) and `#backdrop` (the ambient tint: a fixed full-screen layer, very dark, set from the theme's `data-kind`/`data-daypart`, ambient theme only).
- Opacity layers, so nothing fights: `#stage` carries `--dim` (brightness), `#fade` carries the relocation fade (`.relocating`), `#content` carries the theme-switch animations. Never put two of these on one element.

Weather effects (all five themes): `src/effects/particles.ts` has a pure, tested simulation core (`createScene`/`stepScene`, injected rng, per-particle `shape`) and a thin canvas renderer (`startEffects`, `#effects` between `#backdrop` and `#stage`). `syncEffects` in `src/main.ts` runs the effect for the forecast's kind/daypart in every theme and `none` only without a forecast; `?fx=` forces one. `intensity` (a parameter of `createScene` and `setWeather`, from `effectIntensity(themeId)`) multiplies every alpha and the flash: ambient 1 and, since the real TV (LG C6) showed 0.6 as invisible, the black themes (minimal, forecast, analog) too (`BLACK_THEME_INTENSITY` = 1; the mechanism stays for tuning). Dimness rule: per-kind alpha caps in `MAX_ALPHA` (rain/storm 0.45, snow 0.55, night stars 0.7, day rays 0.12, clouds 0.15, fog 0.2) times intensity, storm flash at most 12% (`FLASH_PEAK` 0.10, times intensity) for 300 ms every 20-60 s, particle caps in `MAX_PARTICLES`, nothing static, about 30 fps, dt clamped, paused while hidden; the canvas also gets `opacity: var(--dim)`. Rain streaks are 22-52 px long and `STREAK_WIDTH` 1.5 px wide. Clouds (shape `blob`) are layered, not round: `CLOUD_VARIANTS` / `FOG_VARIANTS` define 3-5 overlapping, wide, flat ellipses per sprite (2.5-4:1 for clouds, fog bands 4:1 and wider, a shared flat base), painted once per variant to an offscreen sprite (`cloudSprite`, no per-frame gradients); each cloud particle has an `aspect` (>= 2, fog >= 4) and drifts sideways while bobbing 5-14 px (`baseY`/`bob`). Partly cloudy is its own scene: a few clouds plus light rays by day, or about 40 stars plus clouds by night (cloudy is clouds only). Any new effect must stay inside those limits; add a test for its cap and alpha, including at intensity < 1.

Cinematic theme (`cinematic`, 電影感, the fifth theme, registered last): its own weather engine, `src/effects/cinematic.ts`, ported from `demos/weather/v1-cinematic.html`. Same split as particles: a pure core (`createCineScene` per WeatherKind x daypart via `cineSceneId`, `stepCine` with an injected rng and dt in ms, in a fixed 1920x1080 design space; the step allocates nothing: fixed-size layers, a 36-slot splash pool, one reusable shooting-star record; only a bolt path is built, every 20-60 s) and a thin renderer (`startCinematic`, same `Effects` contract as `startEffects`: sprites painted once and pre-warmed, ~30 fps, `clampDt`, paused while hidden, crossfade on a weather change, canvas scaled from the design space). Caps, asserted in `test/cinematic.test.ts` at intensity 1 and 0.5: `ALPHA_CAP` rain 0.40, clouds 0.18 (a flash may lift a cloud up to, never past, that: `cloudDrawAlpha`), fog 0.20, snow 0.55, stars 0.70, moon 0.32, motes 0.22, sun halo 0.34 x brightness, shooting star 0.45, full-screen flash 0.10 (double pulse, 600 ms), bolt core 0.50; counts in `MAX_COUNTS` (rain 390, snow 274, stars 192, clouds 11, fog 5, splashes 36, motes 34). Schedulers (start to start): lightning 20-60 s, storm only; shooting star 15-45 s, clear/partly at night only. **Only one effects engine draws at a time**: `effectPlan(themeId, still)` (pure) says who owns `#effects`; `syncEffects` in `src/main.ts` stops the idle engine first (an engine told "none" clears the shared canvas) and then starts the active one, so while the cinematic theme is on the regular particles and the meteors are off, and every other theme gets both back. The scene is off, not frozen, under reduced motion (`reducedMotion()`) and `?freeze=1` (a static sun glow would burn in). The theme (`src/themes/cinematic.ts`) is a content-sized column (big clock via `timeHtml`, date with `.shimmer`, one weather line: place, temp, label, range; no icon, no `data-kind`, so no backdrop tint) and must stay that way for the relocation. A new engine or theme that draws on `#effects` must join `effectPlan` and keep to its caps.

Fancy effects (Magic UI-inspired, pure CSS keyframes on transform/opacity; blur only on the `#content` entrance and the `#fade` fade-in after a relocation): (1) meteors, `src/effects/meteors.ts` (pure: `meteorsActive` = clear/partly + night, `nextMeteorDelayMs` 8-25 s, `createMeteor` start in the top/right edge band and end on screen, travel 600-900 px, head alpha at most `METEOR_MAX_ALPHA` 0.35 x intensity) plus `startMeteors`, which creates one `.meteor` element on `#meteors` (fixed, between `#effects` and `#stage`, outside the float) per meteor and removes it on `animationend`; (2) shimmer, `src/effects/shimmer.ts` (pure `nextShimmerDelayMs` 20-60 s; `startShimmer` adds `.shimmer--run` to whatever `.shimmer` elements `#content` holds at that moment, so the per-minute `innerHTML` rebuild is harmless; the element must hug its text, `w-fit`, because it clips the sweep); (3) orbit dots, `orbit` in `src/icons.ts` on the big weather icon only (never the hourly strip, never ambient): three `.wx-orbit` groups of 18/24/30 s infinite rotations, which `syncLoops` already re-syncs because they have infinite iterations; (4) blur-fade, `theme-in-blur` and `#fade.blur-in`. Alpha caps: meteor head 0.35, shimmer peak 0.25, dot 0.4, each asserted by a test (`test/meteors.test.ts`, `test/style.test.ts`). Each is switched off under reduced motion by a scoped rule (`#meteors`, `.shimmer--run::after`, `.wx-orbit`, `#fade.blur-in`, `#content.is-entering`) and meteors/shimmer also by JS (`reducedMotion()`, `freeze.frozen`); `?freeze=1` hides `#meteors`. The dev panel's 特效 checkboxes (`FancyFlags` in `src/devpanel.ts`, persisted) switch each off in dev; the TV always has all four. A new meteor-like decoration must stay under these caps and ship with a reduced-motion rule.

## Layout

- Pure logic with tests: `src/controls.ts`, `src/ha.ts` (protocol; `startHa` takes an injected socket), `src/clock.ts`, `src/burnin.ts` (stage position, zones, relocation timing), `src/keepAwake.ts` (tvpower payloads and reply decision; the bridge wiring takes an injected host), `src/config.ts`, `src/weather.ts`, `src/anim.ts` (digit roll helpers; `syncLoops` is DOM), `src/effects/particles.ts` (core half), `src/effects/cinematic.ts` (core half: scene, step, caps, schedulers, `effectPlan`), `src/effects/meteors.ts` and `src/effects/shimmer.ts` (scheduling and geometry; their `start*` functions are DOM), `src/themes/*`.
- DOM wiring only, untested: `src/main.ts`. Put anything testable in a pure module.
- `demos/` is reference material (standalone weather-scene demos, see `demos/weather/README.md`): excluded from biome (`biome.json`) and from the build, never imported by `src/`. 電影感 was ported from `demos/weather/v1-cinematic.html`.
- Each theme's class names are defined in `src/themes/*`; every utility they use must exist in the built stylesheet (`test/utilities.test.ts`) and every hook class that needs CSS must be styled in `src/styles/`.
- `src/freeze.ts` (pure, tested): the dev-only `?freeze=1` / `?now=` parameters, see README "Freeze". Use them for any screenshot comparison; they are never active from `file://`.

## Styling (Tailwind CSS v4)

`app/style.css` is generated; never edit it. Source: `src/tailwind.css` (entry, layer order `theme < base < components < utilities`, no preflight), `src/styles/theme.css` (`@theme` tokens: `text-fg`, `text-fg-dim`, `text-fg-faint`, `border-line`, `bg-accent`, `font-sans` ("Ambient Sans" first, the bundled font declared in `base.css`, so the TV and a desktop draw the same glyphs; never load a font from the network), `text-tv-30`..`text-tv-300`, `--spacing: 4px`), `base.css`, and the hand-written CSS in `stage.css`, `components.css`, `motion.css`, `dev.css` (all in the `components` layer, so a utility always overrides them).

- Static layout, type size and colour go in the markup as utilities (themes, `app/index.html`, dev panel). Keep the BEM class on the element as a hook.
- Keep as hand-written CSS: burn-in/placement (`#stage`, `#fade`, `#backdrop`, `#effects`: JS sets their transform/opacity), the digit roll, colon, icon animations, theme-switch and forecast-entrance animations, the analog hand sweep, pseudo-elements (`.t-forecast__pop::after`, `.digit--changed::before`), the forecast grid areas, and the reduced-motion block.
- Never build a class name from parts (`text-${x}`, `gap-${n}`): Tailwind only sees full literal names in `src/**/*.ts` and `app/index.html`. Use full names or a lookup table of them (`LINE_SIZES` in `src/themes/minimal.ts`). `test/utilities.test.ts` catches both a missing utility and an interpolated name.
- Layer trap: an unlayered rule beats every layer, so never write unlayered CSS; and a state class toggled from JS (`.show`, `.is-active`) must beat the utility it overrides by specificity (`[&.show]:opacity-100`), not by order.
- To change how a theme looks without moving a pixel unintentionally, compare before/after with `?freeze=1` screenshots (README).

## Tooling note

`patches/fstream@1.0.12.patch` (via `patchedDependencies`) adapts fstream to the promise-based mkdirp 3 that `@webos-tools/cli` pulls in; without it `ares-package` fails with "mkdir is not a function". Drop the patch if the CLI fixes this.

## Reduced motion

Every rule inside `@media (prefers-reduced-motion: reduce)` in `src/styles/*.css` (it lives in `motion.css`) must have selectors starting with `html:not(.force-motion)` (checked by `test/style.test.ts`), and JS asks `reducedMotion()` in `src/main.ts` (backed by `isReducedMotion` in `src/devpanel.ts`), never `matchMedia` directly. That is what the dev panel's 強制動畫 toggle (`html.force-motion`) switches off; the TV never sets the class.
